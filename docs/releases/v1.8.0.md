# v1.8.0 邮箱验证码恢复与认证邮件 worker

## 已实施内容

- 普通用户与管理员分域的密码恢复页面和 API，包含 OTP、密码策略、Redis 限流、会话撤销和恢复审计。
- 管理员身份与 Better Auth 凭据收敛、管理员激活、委派重置、CLI 恢复、邮箱变更确认及安全审计。
- AES-256-GCM 加密的 `AUTH_EMAIL_DISPATCH` 持久化队列：SMTP 接受后才创建五分钟 OTP，重试、十五分钟死信和旧密钥轮换兼容。
- 受 token 保护的 Vercel Scheduled Route Handler、外部每分钟定时器、共享数据库租约、运行历史、健康降级和应急 HTTP 入口。
- 后台“任务调度”页签，`worker.view` / `worker.manage` 权限，启用前依赖预检与手动执行。

## 已验证证据

- Prisma 迁移 `20260719130000_auth_email_worker` 与 `20260719133000_auth_email_worker_permissions` 已应用到配置的 Neon 数据库。
- Jest：114 个套件通过，415 项通过，1 项跳过；TypeScript 和 Next.js 生产构建通过。
- `npm run docs:check` 通过。

## 发布门禁

- 当前生产目标为 Vercel。cron-job.org 等外部定时器必须每分钟向受保护的 `POST /api/internal/auth-email-jobs/scheduled` 发送正确的 Bearer token；HTTP `200` 仅证明路由可达，不能替代 worker 处理证据。
- 必须由拥有 `worker.manage` 的超级管理员在“系统设置 > 任务调度”完成依赖预检并启用 worker，确认外部触发产生 `SCHEDULED` 运行记录、心跳和健康状态。
- 必须使用两个测试邮箱验收普通用户与管理员 OTP 恢复、死信和故障恢复；随后运行全部发布质量门禁，更新发布证据后才能创建 `v1.8.0` Git tag / GitHub Release。具体步骤见 [验收 runbook](../runbooks/v1.8-password-recovery-acceptance.md)。
