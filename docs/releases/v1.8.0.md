# v1.8.0 邮箱验证码恢复与认证邮件 worker

## 已实施内容

- 普通用户与管理员分域的密码恢复页面和 API，包含 OTP、密码策略、Redis 限流、会话撤销和恢复审计。
- 管理员身份与 Better Auth 凭据收敛、管理员激活、委派重置、CLI 恢复、邮箱变更确认及安全审计。
- AES-256-GCM 加密的 `AUTH_EMAIL_DISPATCH` 持久化队列：SMTP 接受后才创建五分钟 OTP，重试、十五分钟死信和旧密钥轮换兼容。
- Netlify 每分钟 Scheduled Function、共享数据库租约、运行历史、健康降级和 token 保护的应急 HTTP 入口。
- 后台“任务调度”页签，`worker.view` / `worker.manage` 权限，启用前依赖预检与手动执行。

## 已验证证据

- Prisma 迁移 `20260719130000_auth_email_worker` 与 `20260719133000_auth_email_worker_permissions` 已应用到配置的 Neon 数据库。
- Jest：114 个套件通过，415 项通过，1 项跳过；TypeScript 和 Next.js 生产构建通过。
- `npm run docs:check` 通过。

## 发布门禁

- 已于 2026-07-20 合并并推送 `main`（`f59a938`），但 Netlify Published deploy 因账户额度不足被跳过：`Skipped due to account credit usage exceeded`。恢复额度并重新部署前，不得启用远程 worker 或创建 `v1.8.0` Git tag / GitHub Release。
- 必须在 Netlify Published deploy 确认 `auth-email-worker` 显示为 Scheduled；Preview 只使用受权限保护的手动执行验收。
- 必须使用隔离环境的真实 Redis、SMTP 和两个测试邮箱验收普通、管理员、委派与 CLI 恢复、死信和故障恢复。具体步骤见 [验收 runbook](../runbooks/v1.8-password-recovery-acceptance.md)。
