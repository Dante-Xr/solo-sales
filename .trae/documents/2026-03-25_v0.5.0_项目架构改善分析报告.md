## 二、具体问题分析

### 2.1 状态管理架构问题 🔴

#### 问题 1: 混合的状态管理模式

**当前状态**:
```
CartContext (本地状态) + Redis (服务端缓存) + localStorage (持久化)
```

**问题描述**:
- 购物车状态存在三个地方：Context、Redis、localStorage
- 状态同步逻辑分散在多个文件
- 服务器端无法获取客户端购物车真实状态

**改善建议**:
```
推荐方案：TanStack Query (React Query) + 服务器状态

优势：
1. 统一的服务器状态管理
2. 自动缓存 + 轮询 + 乐观更新
3. 内置请求去重和错误处理
4. 减少 Context 滥用

实施：
- 移除 CartContext 中的本地缓存逻辑
- 使用 useCart() → useCartQuery() + useCartMutation()
- Redis 仅作为缓存层，不作为主数据源
```

#### 问题 2: 缺乏 Server State 抽象

**当前状态**:
- 所有数据获取直接调用 Prisma/Redis
- 无 Repository 模式
- 无 Service 层

**改善建议**:
```
src/
├── repositories/          # 数据访问层
│   ├── ProductRepository.ts
│   ├── OrderRepository.ts
│   └── UserRepository.ts
├── services/             # 业务逻辑层
│   ├── ProductService.ts
│   ├── OrderService.ts
│   └── CartService.ts
├── api/                  # API 路由（仅做请求转发）
└── repositories/index.ts  # 统一导出
```

### 2.2 API 层架构问题 🟡

#### 问题 3: API 路由缺乏统一模式

**当前状态**:
```typescript
// 每个 API 路由都是独立实现
export async function GET(request: NextRequest) {
  try {
    // 重复的校验逻辑
    // 重复的错误处理
    // 重复的响应格式
  } catch (error) {
    return NextResponse.json({ success: false, error: "..." }, { status: 500 })
  }
}
```

**问题描述**:
- 每个 API 都有重复的 try-catch、错误处理
- 无统一错误类
- 无请求拦截器

**改善建议**:
```typescript
// 1. 创建统一错误类
class AppError extends Error {
  constructor(
    public code: string,
    public message: string,
    public statusCode: number = 500
  ) {
    super(message)
  }
}

// 2. 创建 API 包装器
export function withAuth(
  handler: (req: Request, ctx: Context) => Promise<Response>,
  options?: { permissions?: string[] }
) {
  return async (req: Request, ctx: Context) => {
    try {
      const admin = await verifyAdminToken(req)
      if (!admin) throw new AppError("UNAUTHORIZED", "未登录", 401)
      if (options?.permissions) {
        const hasAccess = await hasPermission(admin.id, options.permissions)
        if (!hasAccess) throw new AppError("FORBIDDEN", "无权限", 403)
      }
      return handler(req, { ...ctx, admin })
    } catch (error) {
      if (error instanceof AppError) {
        return NextResponse.json(
          { success: false, error: error.message, code: error.code },
          { status: error.statusCode }
        )
      }
      return NextResponse.json(
        { success: false, error: "内部错误" },
        { status: 500 }
      )
    }
  }
}

// 3. 使用示例
export const GET = withAuth(async (req, ctx) => {
  const products = await productRepository.findAll()
  return NextResponse.json({ success: true, data: products })
}, { permissions: ["products.view"] })
```

#### 问题 6: 权限系统前端集成缺失

**当前状态**:
- `usePermissions` hook 被删除
- 后端权限校验已完善
- 前端无权限控制

**问题**: 用户无法在前端看到基于权限的 UI 差异

**改善建议**:
```typescript
// 恢复 usePermissions hook
// src/hooks/usePermissions.tsx

"use client"
import { createContext, useContext, useState, useEffect, useCallback, ReactNode } from "react"

interface PermissionContextType {
  permissions: string[]
  hasPermission: (permission: string) => boolean
  hasAnyPermission: (permissions: string[]) => boolean
  hasAllPermissions: (permissions: string[]) => boolean
  isLoading: boolean
  refresh: () => Promise<void>
}

const PermissionContext = createContext<PermissionContextType | null>(null)

export function PermissionProvider({ children }: { children: ReactNode }) {
  const [permissions, setPermissions] = useState<string[]>([])
  const [isLoading, setIsLoading] = useState(true)

  const fetchPermissions = useCallback(async () => {
    try {
      const res = await fetch("/api/admin/auth/me")
      const data = await res.json()
      if (data.success) {
        setPermissions(data.data.permissions)
      }
    } finally {
      setIsLoading(false)
    }
  }, [])

  useEffect(() => {
    fetchPermissions()
  }, [fetchPermissions])

  const hasPermission = useCallback((permission: string) => {
    return permissions.includes("*") || permissions.includes(permission)
  }, [permissions])

  const hasAnyPermission = useCallback((perms: string[]) => {
    return perms.some(p => hasPermission(p))
  }, [hasPermission])

  const hasAllPermissions = useCallback((perms: string[]) => {
    return perms.every(p => hasPermission(p))
  }, [hasPermission])

  return (
    <PermissionContext.Provider value={{
      permissions,
      hasPermission,
      hasAnyPermission,
      hasAllPermissions,
      isLoading,
      refresh: fetchPermissions
    }}>
      {children}
    </PermissionContext.Provider>
  )
}

export const usePermissions = () => {
  const context = useContext(PermissionContext)
  if (!context) throw new Error("usePermissions must be used within PermissionProvider")
  return context
}

// 权限指令组件
export const RequirePermission = ({
  permission,
  children,
  fallback = null
}: {
  permission: string
  children: ReactNode
  fallback?: ReactNode
}) => {
  const { hasPermission } = usePermissions()
  return hasPermission(permission) ? <>{children}</> : <>{fallback}</>
}
```

#### 问题 10: 缺乏错误边界

**当前状态**: 无 ErrorBoundary 组件

**问题**: 子组件崩溃导致整个应用白屏

**改善建议**:
```typescript
// src/components/error/ErrorBoundary.tsx
"use client"

import { Component, type ReactNode } from "react"

interface Props {
  children: ReactNode
  fallback?: ReactNode
}

interface State {
  hasError: boolean
  error?: Error
}

export class ErrorBoundary extends Component<Props, State> {
  constructor(props: Props) {
    super(props)
    this.state = { hasError: false }
  }

  static getDerivedStateFromError(error: Error): State {
    return { hasError: true, error }
  }

  componentDidCatch(error: Error, errorInfo: React.ErrorInfo) {
    console.error("ErrorBoundary caught:", error, errorInfo)
  }

  render() {
    if (this.state.hasError) {
      return this.props.fallback || (
        <div className="p-4 text-center">
          <h2 className="text-lg font-semibold">出错了</h2>
          <p className="text-muted-foreground">{this.state.error?.message}</p>
          <button
            onClick={() => window.location.reload()}
            className="mt-4 px-4 py-2 bg-primary text-white rounded"
          >
            刷新页面
          </button>
        </div>
      )
    }
    return this.props.children
  }
}
```

### 2.6 缓存架构问题 🟡

#### 问题 11: Redis Mock 值允许进入生产

**当前状态**:
```typescript
// src/lib/redis.ts
catch (error) {
  console.warn("Redis 配置验证失败，使用 Mock 模式:", error)
  redis = new Redis({
    url: "https://mock.upstash.io",
    token: "mock-token",
  })
}
```

**问题**: 生产环境可能使用 Mock 值，导致缓存失效

**改善建议**:
```typescript
// src/lib/redis.ts
const redis = (() => {
  const url = process.env.UPSTASH_REDIS_REST_URL
  const token = process.env.UPSTASH_REDIS_REST_TOKEN

  // 生产环境必须配置真实 Redis
  if (process.env.NODE_ENV === "production") {
    if (!url || !token) {
      throw new Error("生产环境必须配置 UPSTASH_REDIS_REST_URL 和 UPSTASH_REDIS_REST_TOKEN")
    }
    return new Redis({ url, token })
  }

  // 开发环境允许 Mock
  if (!url || !token) {
    console.warn("Redis 未配置，使用内存模拟")
    return new Redis({ url: "https://mock.upstash.io", token: "mock" })
  }

  return new Redis({ url, token })
})()

export default redis
```
