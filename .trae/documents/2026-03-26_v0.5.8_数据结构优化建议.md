# v0.5.8 数据结构优化建议

## 一、数据库 Schema 问题与建议

### 1. Product 模型 - JSON 类型滥用问题

**当前设计**
```prisma
images      String[]  // PostgreSQL String[] 类型
```

**问题**：`String[]` 是 PostgreSQL 原生数组类型，检索效率低，且无法对单个图片进行元数据管理（如压缩率、CDN状态）。

**建议**：创建独立的 `ProductImage` 关联表

```prisma
model ProductImage {
  id        String  @id @default(cuid())
  productId String
  product   Product @relation(fields: [productId], references: [id])
  url       String
  position  Int     @default(0)
  isPrimary Boolean @default(false)
  createdAt DateTime @default(now())

  @@index([productId])
}
```

---

### 2. Order 模型 - 缺少金额精度处理

**当前设计**
```prisma
totalAmount Float    // 使用 Float 会导致精度问题
```

**问题**：金融数据使用 `Float` 会产生 `0.1 + 0.2 = 0.30000000000000004` 的问题。

**建议**：改用 `Decimal` 类型（Prisma 支持）

```prisma
totalAmount Decimal  @db.Decimal(10, 2)
price       Decimal  @db.Decimal(10, 2)
```

---

### 3. User 模型 - 缺少登录追踪

**建议**：添加登录失败锁定机制

```prisma
failedLoginAttempts  Int      @default(0)
lockoutUntil         DateTime?
lastLoginIp          String?
```

---

### 4. AbandonedCart - cartData JSON 冗余设计

**问题**：当前 `cartData Json` 存储完整购物车内容，但商品价格等信息可能随时间变化。

**建议**：改为存储购物车快照的压缩版本，或仅存储 `cartItemIds` 引用

```prisma
cartItems    Json     // 购物车商品快照（价格随时间变化需重建）
cartSnapshotHash String?  // 用于检测购物车内容是否变更
```

---

## 二、Context/状态管理问题

### 5. CartContext - 持久化缺失

**当前问题**：`CartContext` 数据仅存于内存，刷新页面后丢失。

**建议**：添加 localStorage 持久化

```typescript
// CartContext.tsx 优化
useEffect(() => {
  const saved = localStorage.getItem('cart')
  if (saved) setCart(JSON.parse(saved))
}, [])

useEffect(() => {
  localStorage.setItem('cart', JSON.stringify(cart))
}, [cart])
```

---

### 6. 缺少统一的全局状态管理

**当前问题**：多个 Context 零散分布，跨组件通信困难。

**建议**：使用 Zustand 或 Jotai 创建统一 Store

```typescript
// src/store/index.ts
interface AppStore {
  cart: CartItem[]
  wishlist: string[]
  user: User | null
  // ...
}
```

---

## 三、API 设计问题

### 7. Products API - N+1 查询风险

**当前代码**
```typescript
include: {
  category: { select: { id: true, name: true } },
  reviews: true  // 如果 reviews 数量多，这会导致 N+1
}
```

**问题**：当商品数量多时，`reviews` 的 include 会触发 N+1 查询。

**建议**：使用 `select` 限制返回字段，或添加 `@relation(..., count: true)` 获取评价数量

```typescript
include: {
  category: { select: { id: true, name: true } },
  _count: { select: { reviews: true } }  // 仅返回数量，不加载详情
}
```

---

### 8. 批量操作缺少事务包装

**当前**：`/api/products/batch/route.ts` 的批量操作未使用 Prisma Transaction。

**建议**：

```typescript
await prisma.$transaction([
  prisma.product.updateMany({
    where: { id: { in: ids }},
    data: { isPublished: true }
  }),
  prisma.stockAlert.createMany({ data: alerts })
])
```

## 四、性能优化建议

### 9. 数据库索引优化空间

**当前已有索引**
```prisma
@@index([categoryId])
@@index([isPublished])
@@index([name])
```

**建议**：添加复合索引优化常见查询模式

```prisma
@@index([categoryId, isPublished, createdAt])  // 分类+发布状态+时间
@@index([isPublished, price])                  // 价格筛选+排序
```

---

### 10. AbandonedCart 缺少关键索引

**当前**
```prisma
@@index([userId])
@@index([status])
@@index([createdAt])
```

**建议**：添加复合索引

```prisma
@@index([status, createdAt])  // 查询待处理且过期的废弃购物车
@@index([userId, status])      // 用户+状态联合查询
```

---

## 五、数据一致性建议

### 11. 库存同步问题

**风险**：`Product.stock` 与实际订单扣减可能不一致（并发下单时）。

**建议**：使用数据库行级锁或乐观锁

```typescript
// 订单创建时
const product = await prisma.$transaction(async (tx) => {
  const p = await tx.product.findUnique({ where: { id: productId }})
  if (p.stock < quantity) throw new Error('库存不足')
  return tx.product.update({
    where: { id: productId, stock: { gte: quantity } }, // 乐观锁
    data: { stock: { decrement: quantity }}
  })
})
```

---

### 12. 优惠券超发风险

**当前**：`Coupon.usedCount` 可能与实际 `CouponUsage` 数量不一致。

**建议**：在 `CouponUsage` 表添加唯一约束，并通过数据库侧来保证一致性

```prisma
model CouponUsage {
  id          String   @id @default(cuid())
  couponId    String
  userId      String
  orderId     String

  // 添加复合唯一约束防止重复使用
  @@unique([couponId, userId])
}
```

## 六、迁移执行优先级

| 优先级 | 建议 | 风险 | 工作量 |
|--------|------|------|--------|
| 高 | `Float` → `Decimal` | 需数据迁移 | 中 |
| 高 | 添加强制索引 | 无风险 | 低 |
| 中 | 创建 `ProductImage` 表 | 需代码改造 | 高 |
| 中 | CartContext 持久化 | 低风险 | 低 |
| 低 | 统一状态管理 (Zustand) | 重构较大 | 高 |
